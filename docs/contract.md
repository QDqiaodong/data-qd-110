# 批次图与质量口径

JSON 顶层 lots/recipes 数组。lot: lot_id 唯一非空、kind=raw|produced、mass_g 正整数克。
recipe: output_lot、inputs（lot_id,mass_g 正整数）、loss_g 非负整数；单项质量不超过10^12克。
每个 produced 恰好一个配方，raw 无配方。输入批次存在且在单配方内不重复。
每批总消耗不得超过其产出质量；每道配方投入=产出+损耗；图必须无环。
一个配方只产一个批次，多种产物分摊和返工循环不支持。配方顺序不影响拓扑处理。

假定完全均匀混合，损耗也按相同比例带走来源物料。这是合成业务的显式假定，
并非真实工艺的普遍规律。输出来源比例=各投入克数加权的父批来源比例。
Fraction 精确有理数计算，避免多级混合舍入。origin_mix 分子/分母以文本保存，
避免多级分母超出SQLite整数范围。available_origin_estimate是方便查询的浮点近似，
正式精确值在命令行 JSON 的 available_origin_g 与来源分数中。

available_g=本批质量-所有配方消耗，不把中间产物的总量重复算作最终可用量。
全图原料总质量=剩余所有批次可用质量+全部工序损耗。JSON 输出投入、损耗、
拓扑顺序、各批剩余及来源比例。SQLite 存储批次、加工事实、投入边和来源矩阵，
开启外键，使用临时完整快照替换；重复执行不叠加。失败保持旧目标不变。
输入是完整合成加工快照，不支持并发发布或在有活跃连接时替换目标。
不做仓库库存管理、真实召回决策、销售流转或材料质量认证。
